3. Зачем нужен ПИД регулятор, как им пользоваться, куда устанавливать датчики температуры для ПИД регулировки?
**Зачем нужен PID‑регулятор?** 
• Он обеспечивает точную и плавную подачу тепла, удерживая заданную температуру без больших колебаний. 
• С помощью коэффициентов P, I, D можно быстро реагировать на изменения внешней среды (P), устранять постоянную ошибку (I) и сглаживать резкие отклонения (D).

**Как пользоваться PID‑регулятором SmartTherm** 
1. **Включите контроллер** и дождитесь перехода в режим работы по OpenTherm (LED мигает один раз в 2 с).
2. Откройте веб‑интерфейс (IP‑адрес, указанный в меню Debug → WiFi).
3. Перейдите в раздел “PID Settings” (если его нет, добавьте в коде).
4. Начните с базовых значений: 
 • P = 120 
 • I = 0.01 
 • D = 0. 
5. Наблюдайте за графиками в Debug → “PID” (U, dP, dI, dD). 
6. **Тест‑настройка** 
 – Увеличивайте P до появления небольших колебаний, затем снизьте на 20 %. 
 – Если температура медленно «плавится» к уставке, включите I = 0.01‑0.02. 
 – При резких скачках добавьте D = 1‑3 (не более 5). 
7. После каждой корректировки **нажмите кнопку Reset PID** (если меняете коэффициенты или уставку > 3 °C). Это очистит накопленную интегральную составляющую dI.

**Куда устанавливать датчики температуры** 
- **Т1** (датчик наружной/внутренней температуры) подключается к разъёму Jack 3.5 мм – левый канал (Tip) = питание, правый (Ring) = Data, общий (Sleeve) = GND. 
- **Т2** (датчик температуры в системе отопления) подключается к другому порту Jack 3.5 мм (или к назначенному пину, если используется другой модуль). 
- Для ESP8266: Т1 = D6, Т2 = D2. 
- Для ESP32: Т1 = D15, Т2 = D26. 

**Итого**: PID‑регулятор позволяет держать температуру в заданном диапазоне, а датчики, подключённые по указанным портам, дают контроллеру данные для расчётов.

4. Что такое погодозависимая автоматика(ПЗА) как ее можно использовать вместе с контроллером смарттерм
**Погодозависимая автоматика (ПЗА)** – это логика, которая корректирует подачу тепла в зависимости от прогноза погоды. 
Она позволяет заранее снизить или повысить уставку температуры, учитывая ожидаемые изменения наружной температуры, солнечную радиацию и ветровые потери, тем самым уменьшая нагрузку на котёл и повышая комфорт.

**Как подключить ПЗА к SmartTherm**

1. **Получить прогноз погоды в Home Assistant** 
 • Используйте интеграцию `met.no`, `openweathermap` или `yr.no`. 
 • Создайте `template sensor`, который возвращает температуру за 6‑24 ч в будущем.

2. **Расчёт корректировки** 
 ```yaml
 template:
 - sensor:
 - name: "temp_setpoint_adj"
 unit_of_measurement: "°C"
 state_class: measurement
 value_template: >-
 {% set forecast = states('sensor.forecast_temperature') | float %}
 {% set today = states('sensor.current_temperature') | float %}
 {% set delta = forecast - today %}
 {% if delta > 3 %}
 -2.5
 {% elif delta < -3 %}
 2.5
 {% else %}
 0
 {% endif %}
 ```

3. **Передать новое значение в SmartTherm** 
 *Если SmartTherm подключён к HA через MQTT* 
 ```yaml
 automation:
 - alias: "ПЗА – обновление уставки"
 trigger:
 - platform: state
 entity_id: sensor.temp_setpoint_adj
 action:
 - service: mqtt.publish
 data:
 topic: "smarttherm/setpoint"
 payload: "{{ states('sensor.temp_setpoint_adj') | float + 45 }}"
 ```
 *Если SmartTherm имеет веб‑API* – используйте `http`‑запрос вместо MQTT.

4. **Проверка работы** 
 • В логах SmartTherm убедитесь, что получено новое значение. 
 • Сравните частоту включений котла до и после включения ПЗА.

**Мини‑пример кода для SmartTherm (ESP32)**

```cpp
**include <WiFi.h>**
**include <PubSubClient.h>**

const char* ssid = "YOUR_WIFI_SSID";
const char* password = "YOUR_WIFI_PASS";
const char* mqttServer = "192.168.1.10"; // HA MQTT broker

WiFiClient espClient;
PubSubClient client(espClient);

void setup {
 Serial.begin(115200);
 WiFi.begin(ssid, password);
 while (WiFi.status != WL_CONNECTED) delay(500);
 client.setServer(mqttServer, 1883);
}

void loop {
 if (!client.connected) reconnect;
 client.loop;
}

void reconnect {
 while (!client.connected) {
 if (client.connect("SmartTherm")) {
 client.subscribe("smarttherm/setpoint");
 } else delay(5000);
 }
}

void callback(char* topic, byte* payload, unsigned int length) {
 if (strcmp(topic, "smarttherm/setpoint") == 0) {
 char buf[32];
 memcpy(buf, payload, length);
 buf[length] = '\0';
 float setpoint = atof(buf);
 setHeatingSetpoint(setpoint); // пользовательская функция
 }
}
```

**Итого** 
ПЗА – это автоматическое регулирование температуры подачи, основанное на погодном прогнозе. С помощью Home Assistant, MQTT и простых шаблонов вы можете подключить эту логику к SmartTherm, снизив потребление газа и повысив комфорт.

5. Почему же температура теплоносителя оказывется больше той, что ограничена ПЗА
**Коротко:** 
Теплоноситель может выйти за пределы заданной ПЗА из‑за «перехода» (overshoot) PID‑регулятора, задержки датчика, гистерезиса включения/выключения котла и ограничений самого котла (максимальная мощность, минимальный режим работы). 

**Пошаговый разбор:**

• **Параметры PID** 
 - *P* (пропорциональная часть) слишком велика → мгновенное «подгонка» к уставке, но при быстром отклике нагревателя может «перепрыгнуть» выше. 
 - *I* (интегральная часть) медленно растёт → при долгой работе система «собирает» ошибку и может подать слишком большую мощность, пока не «соберётся» к уставке. 
 - *D* (дифференциальная часть) отсутствует → нет сглаживания резкого отклика. 

• **Гистерезис CHStartGist** 
 При включении котла он стартует только после того, как температура падёт ниже (T‑Indoor – CHStartGist). Если CHStartGist слишком мал, котёл включается слишком часто, а при включении он может «перегореть» до уровня, превышающего ПЗА. 

• **Сенсорная задержка** 
 Датчик DS18B20 (или аналог) имеет время наёмки, а также может быть размещён в месте с сквозняком. Температура, которую видит контроллер, может быть ниже реальной, поэтому регулятор подаёт больше мощности. 

• **Ограничения котла** 
 - Минимальная мощность (часто 20–30 %) заставляет котёл работать в «сильном» режиме, пока не достигнет нужной температуры. 
 - Максимальная мощность ограничена, но при большом тепловом сопротивлении системы температура может «залипать» выше, пока не стабилизируется. 

**Как исправить:**

1. Уменьшить *P* на 10–20 % (пример: 100 → 80). 
2. Увеличить *I* до 0.02–0.03, если колебания медленные. 
3. Добавить *D* (1–3). 
4. Увеличить CHStartGist до 3–5 °C, чтобы котёл включался позже. 
5. Переместить датчик ближе к теплообменнику, убрать сквозняки. 
6. Проверить, что в меню контроллера включён режим PID и что «модуляция» (PWM) находится в диапазоне 60–100 % при прогреве. 

**Пример кода (C++/Arduino) для установки предельных значений PID в SmartTherm:**

```cpp
**include <SmartThermPID.h>**

SmartThermPID pid;

// Установить пределы температуры
pid.setSetpoint(70); // желаемая температура 70 °C
pid.setLimits(50, 80); // минимум 50 °C, максимум 80 °C

// Настроить коэффициенты
pid.setCoefficients(80, 0.02, 2); // P, I, D
pid.setHysteresis(3); // CHStartGist 3 °C
```

6. Может ли контроллер смарттерм управлять кроме котла еще и бойлером косвеного нагрева
**Ответ** 
SmartTherm управляет устройствами, которые поддерживают протокол OpenTherm. Если ваш бойлер косвеного нагрева (например, газовый или электрический) имеет интерфейс OpenTherm и клеммы OT+ / OT‑, то контроллер может подключиться к нему так же, как к обычному газовому котлу. Если OpenTherm в бойлере отсутствует – прямого управления SmartTherm нет, но можно добавить внешний адаптер OT‑шины, если в бойлере есть «комнатный» термостат (клемма 3‑4). 

**Пошаговая инструкция** 

1. **Проверка совместимости** 
 • Убедитесь, что бойлер оснащён клеммами OT+ / OT‑ (обычно 6‑7 или 8‑9). 
 • Если бойлер имеет «комнатный» термостат, подключите к нему адаптер OpenTherm (OT‑шина). 
 • При отсутствии OT‑шины в бойлере, можно использовать модуль OT‑адаптер, подключённый к клеммам 3‑4. 

2. **Подключение** 
 • Подключите ESP32 к 5 V и GND (или к USB‑питанию). 
 • Пины OpenTherm на ESP32: 
 – **IN** → TX (GPIO17) 
 – **OUT** → RX (GPIO16) 
 – 3.3 V → питание OT‑адаптера 
 – GND → общий. 
 • Клеммы OT+ / OT‑ на адаптере соедините с соответствующими клеммами бойлера. 

3. **Датчики температуры** 
 • Если нужен контроль температуры воды в бойлере, подключите DS18B20 к GPIO25 (Data), 3.3 V и GND, подтягивающий резистор 4.7 kΩ. 

4. **Настройка прошивки** 
 • Загрузите стандартную прошивку SmartTherm из репозитория: 
 https://github.com/Evgen2/SmartTherm 
 • В веб‑интерфейсе (после подключения к Wi‑Fi) выберите «Configure new AP», подключитесь к сети вашего дома и проверьте, видит ли контроллер OpenTherm‑шину бойлера. 

5. **Тестирование** 
 • После подключения к сети, в меню «Debug» проверьте статистику OpenTherm – должна появляться активность. 
 • Убедитесь, что бойлер реагирует на команды от SmartTherm (запуск/остановка нагрева, изменение температуры). 

**Кратко** 
Да, SmartTherm может управлять бойлером косвеного нагрева, если он оснащён OpenTherm‑интерфейсом (или имеет клемму для «комнатного» термостата). В противном случае потребуется добавить OT‑адаптер или использовать другой контроллер, поддерживающий конкретный протокол бойлера.

7. Какая максимальная длина шнура датчика DS18B20, который подключается к контроллеру смарттерм (10 м)
**Ответ** 
Для SmartTherm длина шнура DS18B20 до 10 м считается безопасной при стандартных условиях (простой провод 0,5 мм², pull‑up 4,7 кОм). При более длинном кабеле (до 50–100 м) требуется экранированная витая пара и более сильный pull‑up (2,2–3,3 кОм) либо активный повторитель.

**Как подключить DS18B20 (10 м)** 
• Проверьте, чтобы кабель был не более 0,5 мм² и не более 10 м. 
• Подключите VCC к 3,3 В ESP32, GND к GND, DATA к выбранному GPIO (например GPIO15). 
• Поставьте pull‑up‑резистор 4,7 кОм между DATA и 3,3 В. 
• В меню SmartTherm → Sensors → T‑Indoor (или T‑Outdoor) укажите GPIO15, нажмите Scan. 
• Сохраните и перезагрузите контроллер; температура должна отображаться корректно.

**Совет** 
Если хотите использовать более длинный шнур (выше 10 м), замените обычный провод на экранированную витую пару (Cat‑5e) и уменьшите pull‑up до 2,2 кОм; это уменьшит задержку сигнала.

8. Почему мо контроллер смарттерм иногда сам перезагружается
**Кратко.** 
SmartTherm может перезагружаться из‑за нестабильного питания, перегрева, ошибок прошивки или срабатывания Watchdog‑таймера. 

**Пошаговый чек‑лист диагностики**

• **Питание** 
 – Проверьте, что напряжение от USB‑адаптера находится в диапазоне 4,5–5,5 В (см. схему на странице продукта). 
 – Попробуйте заменить кабель и/или блок питания. 

• **Температура** 
 – Убедитесь, что контроллер не перегревается (проверьте расположение в корпусе, отсутствие перегрева модулей ESP). 

• **Firmware** 
 – Откройте веб‑интерфейс → Setup → Firmware → проверьте версию. 
 – Если версия < 0.74, обновите до последней, скачав из репозитория: https://github.com/Evgen2/SmartTherm 

• **Watchdog** 
 – В логах (Setup → Log) ищите строки вида `WDT reset`. 
 – Если их много, уменьшите частоту опроса OpenTherm (Setup → OpenTherm → Poll interval). 

• **Wi‑Fi / MQTT** 
 – Проверьте стабильность соединения: в Setup → Wi‑Fi → RSSI ≥ ‑70 dBm. 
 – Если используется MQTT, убедитесь, что брокер отвечает без задержек. 

• **Пере‑запуск** 
 – Перезагрузите контроллер вручную (Reset‑кнопка). 
 – После перезагрузки проверьте, появятся ли сообщения в логах о «reboot» и «started». 

**Пример проверки логов через MQTT** 
```yaml

 password: pass
 discovery: true

sensor:
 - platform: mqtt
 name: "SmartTherm Logs"
 state_topic: "homeassistant/sensor/SmartTherm/logs"
```
Пусть SmartTherm публикует в `homeassistant/sensor/SmartTherm/logs` строки из `Setup → Log`. 
В Home Assistant вы сможете видеть все сообщения о перезагрузке и ошибках.

10. Может ли контроллер смарттерм работать в связке со свободно распространяемой программой Home Assistant
**Ответ** 
Да, SmartTherm можно интегрировать с Home Assistant (HA) через MQTT. Контроллер поддерживает MQTT‑дискавери, поэтому после настройки брокера в HA он автоматически появится как устройство и будет обмениваться данными (температура, состояние OpenTherm, команды управления).

**Пошаговая настройка**

1. **Запустить MQTT‑брокер** 
 - В HA (Supervisor) → Add‑ons → Mosquitto broker → Install → Start → Enable “Start on boot”. 
 - Создать пользователя и пароль в настройках Mosquitto (Configuration → Users).

2. **Настроить SmartTherm** 
 - В веб‑интерфейсе SmartTherm → Setup → MQTT. 
 - Server = IP‑адрес HA (например 192.168.1.100). 
 - Port = 1883. 
 - Username / Password = созданные в Mosquitto. 
 - Topic prefix = `homeassistant` (или любой, но должен совпадать с `discovery_prefix` в HA). 
 - Enable MQTT Discovery = ON. 
 - Сохранить и перезагрузить контроллер (Reboot).

3. **Проверка в HA** 
 - Через 1‑2 минут в «Devices & Services» появится «MQTT – SmartTherm». 
 - В разделе «Entities» найдите датчики (temperature, status) и службы (setTindoor, setTsetpoint и т.д.).

4. **Отправка комнатной температуры из HA** (пример автоматизации) 

```yaml

trigger:
 - platform: time_pattern
 seconds: /30
action:
 - service: number.set_value
 target:
 entity_id: number.smarttherm_t_indoor
 data:
 value: "{{ states('sensor.livingroom_temperature') | float }}"
```

11. Какие перемычки на плате управления котла отвечают за подключение контроллера смарттерм
**Кратко:** 
На плате управления котла подключение SmartTherm регулируется перемычками, которые включают шину OpenTherm. Обычно это перемычка, помеченная **OT** (или **OpenTherm**), а в некоторых моделях – **F10** (Baxi) или **d.27** (Vaillant). Установите эти перемычки в положение «подключено», а затем подключите адаптер SmartTherm к контактам OT+ и OT‑.

**Шаги:**

• Найдите на плате перемычку с надписью **OT** (или **OpenTherm**). 
• Убедитесь, что она соединена (перемычка «подключена»). 
• Для Baxi‑коксов – перемычка **F10** (нажмите и держите, чтобы включить OpenTherm). 
• Для Vaillant – перемычка **d.27** (включение OpenTherm). 
• После установки перемычек в режиме «ON» подключите к контактам OT+ и OT‑ кабель OpenTherm‑адаптера SmartTherm. 
• В меню котла включите OpenTherm (если требуется), затем проверьте статус подключения в SmartTherm.

12. Умеет ли контроллер самрттерм передавать данные на MQTT
**Ответ:** 
Да, контроллер SmartTherm умеет публиковать данные и принимать команды через MQTT. В прошивке предусмотрён MQTT‑модуль, который можно включить и настроить в меню «Setup → MQTT».

**Краткая инструкция:**

1. **Запустите SmartTherm** и откройте его веб‑интерфейс (IP‑адрес контроллера в сети). 
2. Перейдите в раздел «Setup → MQTT». 
3. Включите переключатель **MQTT Enabled**. 
4. Введите параметры брокера:
 - **Server** – IP‑адрес MQTT‑брокера (например 192.168.1.100). 
 - **Port** – 1883 (или другой, если используется другой порт). 
 - **Username / Password** – если брокер требует авторизацию. 
 - **Topic Prefix** – префикс топиков, например `SmartTherm`. 
 - **Enable MQTT Discovery** – включите, если хотите автодискавер в Home Assistant. 
5. Нажмите **Save** и перезагрузите контроллер. 
6. После перезагрузки SmartTherm начнёт публиковать состояния по топикам вида:
 - `SmartTherm/climate/state` – текущее состояние климата. 
 - `SmartTherm/sensors/temperature` – температуры датчиков. 
 - `SmartTherm/errors` – ошибки и статусы. 

**Отправка команд:**

- Команды публикуются в топики с суффиксом `/set`. 
- Пример: чтобы установить целевую температуру, публикуйте в `SmartTherm/climate/temperature/set` JSON‑payload `{"temperature":22.5}`. 
- Можно использовать любой MQTT‑клиент (MQTT Explorer, Home Assistant services, `mosquitto_pub` и т.д.).

**Подключение к Home Assistant:**

- В HA настройте MQTT‑брокер (или используйте уже существующий). 
- В настройках SmartTherm включите «Enable MQTT Discovery» – HA автоматически создаст сущности `climate.smarttherm`, `number.smarttherm_t_indoor` и др. 

Таким образом, SmartTherm полностью поддерживает передачу данных и управление через MQTT.

13. Умеет ли  контроллер самрттерм передавать данные через ZIGBEE
**Ответ:** 
SmartTherm не имеет встроенного Zigbee‑модуля и не может напрямую передавать данные через Zigbee. 

**Как обойти это ограничение:** 
• Подключите внешнее Zigbee‑координаторное устройство (например, ESP32‑Zigbee, XBee, Zigbee‑gateway). 
• Настройте его так, чтобы он публиковал/подписывался на MQTT‑топики. 
• В SmartTherm включите MQTT‑подключение (в меню «Setup → MQTT»). 
• Используйте одинаковый топик для обмена данными, и Zigbee‑координатор будет выступать «прокси» между SmartTherm и Zigbee‑устройствами. 

Таким образом, прямой Zigbee‑поддержки нет, но интеграция возможна через MQTT‑bridge.

15. Можно ли контролировать давление в системе отопления при помощи контроллера смарттерм
**Ответ** 
Да, SmartTherm может показывать давление в системе, но только если ваш котёл поддерживает запрос OpenTherm ID 18 (CH water pressure). Контроллер сам не измеряет давление – он получает значение из котла через шину OpenTherm.

**Как включить контроль давления**

1. **Подключите SmartTherm к котлу** 
 • Убедитесь, что шина OpenTherm подключена правильно (см. пункт 4.2 инструкции). 
 • Проверьте, что котёл поддерживает OpenTherm ID 18 (в большинстве современных моделей Baxi, Vaillant, Vaillant, Viessmann и др.).

2. **Настройте SmartTherm** 
 • В веб‑интерфейсе (после подключения к Wi‑Fi) откройте «Configure new AP» → «Open SSIDs» → подключитесь к сети котла. 
 • Перейдите в «Debug» → «OpenTherm statistic» – там должно появиться значение ID 18.
 • Если значение отсутствует, проверьте совместимость котла.

3. **Мониторинг в Home Assistant** 
 • Добавьте в `configuration.yaml` sensor для OpenTherm ID 18 (пример ниже).
 ```yaml
 sensor:
 - platform: mqtt
 name: "Boiler Pressure"
 state_topic: "smarttherm/opentherm/18"
 unit_of_measurement: "bar"
 value_template: "{{ value_json.data | float / 1000 }}"
 ```
 • Создайте автоматизацию, чтобы получать уведомления, если давление выходит за пределы 0.8‑2.5 bar.

4. **Проверка в SmartTherm** 
 • В разделе «Debug» → «OpenTherm statistic» можно увидеть число «Получен годный ответ» для ID 18.
 • Если давление ниже 0.8 bar, котёл выдаст ошибку (E10 на Baxi). При > 3 bar сработает предохранительный клапан.

**Важно** 
- Датчик давления должен быть встроен в котёл; SmartTherm не подключает внешний датчик давления. 
- Если ваш котёл не поддерживает ID 18, SmartTherm не сможет отчитываться о давлении.
