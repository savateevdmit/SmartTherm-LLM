# SmartTherm LLM

**«SmartTherm LLM»** – это серверное программное обеспечение, развёртываемое на одном физическом сервере с графическим ускорителем. Область применения – обслуживание пользова-телей контроллеров управления котлом SmartTherm: предоставление ответов на типовые вопросы по настройке, эксплуатации и устранению неисправностей оборудования без участия оператора-человека на первом уровне поддержки.

## Назначение

Система предназначена для автоматизации первой линии технической поддержки SmartTherm. Пользователи задают вопросы через Telegram-бота или веб-чат на сайте компании. Запрос обрабатывается RAG-пайплайном: выполняется семантический поиск по базе знаний, и LLM генерирует ответ с учётом найденного контекста. Наполнение и актуализацию базы знаний обеспечивают операторы и волонтёры через административную веб-панель: они добавляют пары «вопрос — ответ», которые после модерации (модерируются только записи добавленные волонтёрами) становятся доступными для RAG-поиска.

***

## Функциональные требования

### Для пользователей (Telegram-бот и веб-чат)

- Приём текстовых вопросов длиной до 2000 символов через Telegram-бота и веб-чат.
- Генерация ответов на основе RAG-пайплайна: семантический поиск по базе знаний с последующей генерацией ответа LLM.
- Форматирование ответов в Markdown с конвертацией в HTML-разметку для Telegram.
- Уведомление пользователя в случае, если релевантный ответ не найден (расстояние выше порога `RAG_RELEVANCE_THRESHOLD`).

### Для администраторов и операторов (веб-панель)

- Управление базой знаний: создание, редактирование и удаление пар «вопрос — ответ».
- Модерация записей, добавленных волонтёрами: просмотр, принятие или отклонение перед публикацией в базу знаний.
- Прикрепление медиафайлов (PNG, JPG) к ответам, хранение в S3-совместимом хранилище MinIO.
- Управление учётными записями администраторов с разграничением ролей: `admin`, `operator`, `volunteer`.
- Возможность скрыть запись базы знаний от RAG-поиска, не удаляя её.
- Просмотр базы знаний с пагинацией (по 10, 20, 50, 100 записей на страницу).

### Для системы

- Асинхронная обработка запросов через очередь Redis.
- Ленивая загрузка LLM с автоматической выгрузкой из памяти GPU через `LLM_IDLE_UNLOAD_SECONDS` секунд бездействия.
- Автоматическое резервное копирование базы данных MariaDB по расписанию.
- CI/CD-пайплайн через GitHub Actions: деплой по push в ветку `main` по SSH.
- Логирование событий в файлы `.log` и в Telegram-канал (при включённом `TG_LOG_ENABLED`).

## Нефункциональные требования

### Производительность

- Время ответа системы: до 3 минут при запущенной LLM с GPU.
- Пропускная способность: до 1000 API-запросов в день.
- Очередь Redis рассчитана на 1500 ожидающих запросов.
- Telegram-бот поддерживает сообщения до 4096 символов.

### Надёжность

- Расчётное время безотказной работы — 80% в месяц при условии стабильной работы GPU.
- Контейнеры управляются Docker Compose с политикой перезапуска `unless-stopped`.
- Сохранность данных Redis обеспечивается режимом AOF (Append Only File).

### Безопасность

- Аутентификация администраторов через server-side сессии с cookie, пароли хешируются алгоритмом Argon2.
- Защита от CSRF-атак через middleware FastAPI.
- Защита от XSS — все пользовательские данные экранируются перед рендерингом в HTML.
- Весь внешний трафик — только по HTTPS; SSL-терминация на уровне reverse proxy.
- SQL-инъекции исключены использованием ORM SQLAlchemy.

### Масштабируемость и совместимость

- Все сервисы контейнеризированы в Docker, оркестрация через Docker Compose.
- Медиахранилище поддерживает переключение между локальным диском и S3-совместимым MinIO.
- Клиентские интерфейсы доступны через любой браузер (Chrome 100+, Firefox 100+, Safari 14+) на любом устройстве, а также через официальный клиент Telegram на десктопе и мобильных платформах.

## Архитектура

Система состоит из нескольких независимых сервисов, запускаемых через Docker Compose:

| Сервис | Описание |
|---|---|
| `webkb` | Основное FastAPI-приложение: административная панель, HTTP API, обработка запросов |
| `worker` | Фоновый обработчик: забирает задачи из Redis, запускает RAG-пайплайн, возвращает результат |
| `tgbot` | Telegram-бот на aiogram: принимает сообщения, отправляет задачи в Redis, возвращает ответ |
| `webchat` | Веб-чат: отдельный FastAPI-сервис, дублирующий функционал Telegram-бота |
| `llama` | llama.cpp server с CUDA-поддержкой, предоставляет OpenAI-совместимый HTTP API |
| `db` | MariaDB 11.8: основное реляционное хранилище с поддержкой VECTOR-типа |
| `redis` | Redis 7 с AOF: очередь задач и кэш результатов |
| `minio` | S3-совместимое объектное хранилище для медиафайлов |
| `dbbackup` | Планировщик автоматических бэкапов MariaDB |

**Описание взаимодействия с пользователем:**

1. Пользователь отправляет вопрос через Telegram-бота или веб-чат.
2. Интерфейсный сервис (`tgbot` или `webchat`) помещает задачу в очередь Redis.
3. Воркер забирает задачу и проверяет доступность LLM через Docker Engine API.
4. `AnswerService` выполняет RAG-поиск: векторизация запроса, поиск по VECDISTANCE в MariaDB, фильтрация по порогу релевантности.
5. Если релевантный контекст найден — LLM генерирует ответ, если нет — пользователю возвращается сообщение об отсутствии ответа.
6. Ответ форматируется, сохраняется в Redis и доставляется пользователю.

## Установка и запуск

### 1. Клонирование репозитория

```bash
git clone https://github.com/savateevdmit/SmartTherm-LLM.git
cd SmartTherm-LLM
```

### 2. Настройка переменных окружения

```bash
cp .env.example .env
# Заполните .env согласно разделу "Конфигурация"
```

### 3. Подготовка модели

Скачайте GGUF-файл модели (например, `gpt-oss-20b`) и поместите его по пути, указанному в `LLM_MODEL_PATH`.

### 4. Запуск

```bash
docker compose up -d
```

Все сервисы поднимаются автоматически. Административная панель доступна по URL, указанному в `WEBKB_PUBLIC_BASE_URL`.

### 5. Инициализация базы данных

База данных инициализируется автоматически при первом запуске через `app/dbinit.py`.

## База данных

Схема включает четыре основные таблицы:

- **`questions`** — записи базы знаний. Поле `embedding` типа `VECTOR(768)` используется для семантического поиска через `VECDISTANCE`. Поля `review_status` и `is_hidden_from_llm` управляют видимостью записей в RAG-пайплайне.
- **`answers`** — ответы, привязанные к вопросам (`ON DELETE CASCADE`). Поле `visual_path` хранит JSON-массив путей к медиафайлам.
- **`admins`** — учётные записи администраторов. Роли: `admin`, `operator`, `volunteer`. Пароли хранятся в виде Argon2-хешей.
- **`volunteer_notifications`** — уведомления волонтёрам о записях, ожидающих модерации.

***

## Сбор данных

Директория `data collection/` содержит вспомогательные скрипты для наполнения базы знаний. Основной скрипт `tg_messages_extractor.py` извлекает сообщения из Telegram-канала поддержки SmartTherm через библиотеку Telethon и сохраняет их в JSON-формат для последующей обработки и загрузки в систему.
